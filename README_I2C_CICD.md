# I2C Temperature/Humidity Monitor with CI/CD
## Embedded Systems Project with Jenkins Automation

An embedded systems project demonstrating I2C communication, temperature/humidity monitoring on STM32F401RE with SHT31-D sensor, and complete CI/CD pipeline integration.

**Project Highlights:**
- 🔧 I2C communication with SHT31-D sensor
- 📊 Real-time temperature/humidity monitoring
- 🤖 Jenkins CI/CD pipeline automation
- 🧪 Hardware-in-the-Loop (HIL) testing with Python
- 🛠️ Automated build, flash, and test workflow
- 📝 Comprehensive CI/CD documentation

## 🎯 Project Overview

This project demonstrates a complete embedded development workflow with CI/CD integration:

- **STM32 bare-metal development** for I2C sensor communication
- **Jenkins pipeline automation** for build-flash-test cycle
- **Hardware-in-the-Loop testing** using Python test framework
- **Modular batch scripts** for local and CI/CD execution

## Hardware

- **MCU**: STM32F401RE (Nucleo-64 board)
- **Sensor**: SHT31-D temperature & humidity sensor
- **Communication**: I2C (100 kHz), UART2 (115200 baud)
- **Power**: 5V USB via Nucleo board, 3.3V regulated

## Build Instructions

### Prerequisites

- **IDE**: STM32CubeIDE 1.17.0 (includes ARM GCC toolchain)
- **Programmer**: STM32_Programmer_CLI (included with STM32CubeIDE)
- **Python**: Python 3.x (for HIL testing)
- **Jenkins** (optional): For CI/CD pipeline

### Build Locally

The build system uses batch scripts that work both locally and in Jenkins:

```bash
cd I2C_TmpHm_RAM_CICD\ci-cd-tools

# Default: Debug build, all targets
buildi.bat

# Specify build type and target
buildi.bat Debug all      # Build Debug configuration
buildi.bat Release all    # Build Release configuration
buildi.bat Debug clean    # Clean Debug build
```

**What happens during build:**
1. Detects workspace (Jenkins `WORKSPACE` variable or local path)
2. Creates/verifies Debug directory
3. Preprocesses makefile to fix absolute paths
4. Runs `make -j4 all`
5. Generates `.elf`, `.bin`, `.map`, and `.list` files

**Build output** (in `I2C_TmpHm_RAM_CICD/Debug/`):
- `I2C_TmpHm_RAM_CICD.elf` - Executable with debug symbols
- `I2C_TmpHm_RAM_CICD.bin` - Binary for flashing
- `I2C_TmpHm_RAM_CICD.map` - Memory map

### Flash to Device

```bash
cd I2C_TmpHm_RAM_CICD\ci-cd-tools

# Flash Debug build (default)
flashi.bat

# Flash Release build
flashi.bat Release
```

## 🤖 CI/CD Pipeline

### Jenkins Setup

**Local Jenkins Access:**
```bash
# Access Jenkins locally
http://localhost:8080/
```

**GitHub Webhook Setup (Optional):**
```bash
# Start ngrok to expose Jenkins to internet for GitHub webhooks
ngrok.exe http 8080

# Use the ngrok URL in GitHub webhook settings
# Example: https://xxxx-xx-xxx-xxx-xxx.ngrok.io/github-webhook/
```

**Pipeline Configuration:**
1. **Create Pipeline Job** in Jenkins
2. **Configure SCM**: Point to this Git repository
3. **Set Script Path**: `I2C_TmpHm_RAM_CICD/ci-cd-tools/Jenkinsfile_HelloWorld`
4. **Run Pipeline**

### Pipeline Stages

```groovy
pipeline {
    agent any

    environment {
        TOOL_DIR = "${WORKSPACE}\\I2C_TmpHm_RAM_CICD\\ci-cd-tools"
    }

    stages {
        stage('Build') {
            steps {
                bat "\"${TOOL_DIR}\\buildi.bat\" Debug all"
            }
        }

        stage('Flash') {
            steps {
                bat "\"${TOOL_DIR}\\flashi.bat\""
            }
        }

        stage('Test') {
            steps {
                bat "python \"${TOOL_DIR}\\MBC_HIL_Full_Suit_Advanced.py\""
                junit 'test-results.xml'
            }
        }
    }
}
```

## 🔍 Key Features

### Batch Script Architecture

**buildi.bat** - Build wrapper with smart workspace detection:
- Detects Jenkins `WORKSPACE` environment variable
- Falls back to local hardcoded path
- Calls `build.bat` with appropriate parameters
- Works identically in local and Jenkins environments

**build.bat** - Core build logic:
- Creates/verifies build directory
- Preprocesses makefile to replace absolute paths with relative paths
- Executes `make` with parallel jobs (`-j4`)
- Restores original makefile after build

**flashi.bat** - Flash wrapper:
- Supports Debug/Release build selection
- Locates correct `.bin` file
- Calls `flash.bat` with device serial number

### Jenkins Integration

- **Environment Variables**: Uses `${WORKSPACE}` for portable paths
- **Lean Jenkinsfile**: Delegates work to batch scripts
- **JUnit Integration**: Publishes test results for visualization
- **Sequential Stages**: Build → Flash → Test with fail-fast behavior

### Hardware-in-the-Loop Testing

Python test scripts communicate with hardware via UART:
- Send commands to embedded firmware
- Parse responses for validation
- Generate JUnit XML reports
- Support automated regression testing

## Common Issues & Solutions

### Issue: Build fails with "makefile not found"
**Solution**: Ensure you're running from the correct directory or that the Debug folder with makefile exists.

### Issue: Flash fails with "No ST-Link detected"
**Solution**: Check USB connection and verify device serial number matches in `flashi.bat`.

### Issue: Jenkins can't find buildi.bat
**Solution**: Verify `TOOL_DIR` environment variable in Jenkinsfile matches your project structure.

See [Jenkin_note.md](docs/learning/Jenkin_note.md) for detailed troubleshooting.
